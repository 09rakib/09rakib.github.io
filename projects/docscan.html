01 / THE PROBLEM

What the project
needed to do.

Scanning is only one part of keeping documents on a phone. The app also needs to store files, find them again, preview PDFs, edit pages and export copies without losing the originals.

02 / ENGINEERING HIGHLIGHTS

The work behind the interface.

01

Coordinate files and metadata

Document files live in app-private storage while SQLite tracks metadata. Managed deletion stages files and uses a recovery journal so a failed database operation can restore the staged documents.

02

Keep state out of widgets

Riverpod providers connect the presentation layer to document repositories and scanning services. The ML Kit gateway requests PDF and JPEG output and closes its scanner after each scan.

03

Edit and compress safely

The implementation includes perspective-crop geometry and PDF compression workers. Compressed output is saved as a new copy, keeping the original document intact.

Flutter + Riverpod→Scan / edit services→Private files→SQLite metadata

03 / IMPLEMENTED FEATURES

What’s in the project.

  • Document scanning through Google ML Kit, PDF preview, document search and sorting.
  • Saved-page editing with perspective crop geometry, plus PDF compression and export workflows.
  • English and Bangla localization, theme preferences, onboarding, and native sharing.

05 / RESULT & SCOPE

Where the work stands.

DocScan brings scanning, local document management, PDF compression and saved-page editing into an Android app. It supports English and Bangla, native sharing and user-selected exports. The screenshot below shows the implemented compression interface.

Android app; no browser demo is available. ML Kit may need a first-use module download. Store billing and release setup require production configuration. No OCR or cloud backup is claimed.
